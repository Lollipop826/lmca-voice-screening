# 情绪识别模型选择与性能分析

## 📊 当前系统分析

### 现状

- **默认配置**：纯规则方法（关键词匹配）

## 🏆 推荐模型对比

### 1. 纯规则（当前默认）

**优势：**
- ✅ 延迟极低（~2ms）
- ✅ 无需下载模型
- ✅ 可解释性强

**劣势：**
- ❌ 覆盖有限（只识别关键词）
- ❌ 无法理解上下文（"不开心" vs "不是不开心"）
- ❌ 老年人含蓄表达识别差（"还好" 实际是 "不好"）

**适用场景：**
- 快速原型
- 离线环境
- 资源受限设备

---

### 2. RoBERTa + 点评模型（现有可选）

**模型信息：**
```
名称: uer/roberta-base-finetuned-dianping-chinese
训练数据: 大众点评评论（餐饮、服务）
情绪维度: positive/negative 二分类
参数量: ~102M
```

**优势：**
- ✅ 比纯规则准确
- ✅ 理解简单上下文
- ✅ 已集成，即开即用

**劣势：**
- ❌ 领域不匹配（电商评论 ≠ 心理健康）
- ❌ 情绪粗糙（只有正负面）
- ❌ 年轻人网络用语为主

**性能：**
- 首次加载：~3-5秒
- 推理延迟：~30-50ms（CPU）
- 内存占用：~400MB

---

### 3. GoEmotions-zh（🏆 推荐）

**模型信息：**
```
名称: SamLowe/roberta-base-go_emotions-chinese
训练数据: Reddit 评论中文翻译（真实对话）
情绪维度: 27类细粒度
  - admiration, amusement, anger, annoyance, approval
  - caring, confusion, curiosity, desire, disappointment
  - disapproval, disgust, embarrassment, excitement
  - fear, gratitude, grief, joy, love, nervousness
  - optimism, pride, realization, relief, remorse
  - sadness, surprise
参数量: ~102M（与点评模型相同）
```

**映射到7维：**
```python
joy     ← joy, amusement, excitement, gratitude, love, pride
sadness ← sadness, grief, disappointment, remorse
anger   ← anger, annoyance, disgust
fear    ← fear, nervousness
anxiety ← nervousness, fear, embarrassment
calm    ← relief, approval, optimism
confusion ← confusion, surprise, curiosity
```

**优势：**
- ✅ **27类直接覆盖你的7维**
- ✅ 对话场景训练（不是评论）
- ✅ 包含 **nervousness（焦虑）**、**confusion（困惑）**
- ✅ caring（关怀）可用于识别患者对家人的情感
- ✅ 性能与点评模型相同

**劣势：**
- ⚠️ 首次需联网下载（~400MB）
- ⚠️ Reddit 风格偏年轻化（但比点评好）

**性能：**
- 首次加载：~3-5秒
- 推理延迟：~30-50ms（CPU）
- 内存占用：~400MB

**推荐指数：⭐⭐⭐⭐⭐**

### 5. 自定义微调（终极方案）

**基础模型：**
```
hfl/chinese-roberta-wwm-ext
hfl/chinese-bert-wwm-ext
```

**微调流程：**
```python
# 1. 收集数据（500-1000条标注对话）
认知筛查对话：
  - "我最近总是记不住事" → {confusion: 0.7, anxiety: 0.3}
  - "还好，没什么大问题" → {calm: 0.4, sadness: 0.3}（含蓄表达）
  - "孙子很久没来了" → {sadness: 0.6, calm: 0.2}

# 2. 微调（需GPU，约2-4小时）
from transformers import AutoModelForSequenceClassification, Trainer

model = AutoModelForSequenceClassification.from_pretrained(
    "hfl/chinese-roberta-wwm-ext",
    num_labels=7
)
trainer = Trainer(model=model, train_dataset=your_data)
trainer.train()

# 3. 保存并部署
model.save_pretrained("models/emotion-elderly-chinese")
```

**优势：**
- ✅ **完全适配老年人语言**
- ✅ 认知障碍特征表达（"想不起来"、"糊涂"）
- ✅ 含蓄/委婉表达识别（"还好" = 不好）

**成本：**
- ⚠️ 需标注数据（人工成本）
- ⚠️ 需GPU训练（2-4小时）
- ⚠️ 持续优化（收集新数据迭代）

**适用场景：**
- 有标注预算
- 追求极致准确率
- 长期运营产品

## ⚡ 性能影响分析

### 完整对话流程延迟拆解

| 阶段 | 默认配置 | 推荐配置 | 全模型配置 |
|------|---------|---------|-----------|
| **ASR** | 70ms | 70ms | 70ms |
| **文本情绪** | 2ms（规则）| 2ms（规则）| 50ms（RoBERTa）|
| **语音情绪** | 0ms（不启用）| 150ms（Emotion2Vec+）| 150ms（Emotion2Vec+）|
| **多模态融合** | 0ms | 5ms | 5ms |
| **记忆检索** | 4ms | 4ms | 4ms |
| **LLM生成** | 2000ms | 2000ms | 2000ms |
| **TTS合成** | 500ms | 500ms | 500ms |
| **总计** | **2576ms** | **2731ms** | **2779ms** |
| **增加延迟** | baseline | **+155ms** | **+203ms** |
| **延迟占比** | - | **5.7%** | **7.3%** |

### 关键发现

1. **LLM是瓶颈**：占总延迟的 **77%**（2000/2600ms）
2. **情绪识别影响小**：即使全模型，也只增加 **7.3%**
3. **推荐配置**：只增加 155ms，用户几乎感知不到
4. **异步优化空间**：情绪识别可与 LLM 并行

## 💡 异步优化方案（高级）

如果追求极致性能：

```python
import asyncio

async def process_turn_optimized(text, audio_path):
    # 并行执行：LLM生成 + 情绪识别
    llm_task = asyncio.create_task(llm_generate(text))
    emotion_task = asyncio.create_task(classify_multimodal(text, audio_path))
    
    # 等待两者完成
    llm_response, emotions = await asyncio.gather(llm_task, emotion_task)
    
    # 情绪识别完全不阻塞主流程！
    # 仅在需要时（如记忆记录）才使用
    return llm_response, emotions
```

**效果：**
- 情绪识别 150ms **完全隐藏**在 LLM 2000ms 中
- 总延迟不变：2576ms
