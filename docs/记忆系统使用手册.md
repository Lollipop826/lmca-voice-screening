# 长程关系记忆系统使用手册

## 架构边界

`EmotionMemobase` 使用现有 SQLite 作为本地事实源，保证对话链路不依赖网络。配置了 `MEMOBASE_PROJECT_URL` 和 `MEMOBASE_API_KEY` 时，轮次会异步镜像到真实的 `MemoBaseClient`；镜像失败不会阻塞本地记忆。

当前使用的 Memobase Python SDK 是 `memobase==0.0.27`。该 SDK 的客户端入口是 `MemoBaseClient`，完整版 Prompt 中的 `Memobase(storage_path=...)` 示例不是当前 SDK 的有效 API。

## Python API

```python
from src.context_management.emotion_memobase import EmotionMemobase

memory = EmotionMemobase(db_path="data/voice.db")

result = memory.capture_turn(
    patient_id="patient-001",
    user_message="我最近有点焦虑，但喜欢听戏曲。",
    assistant_message="我们慢慢聊，先从您熟悉的话题开始。",
    session_id="session-001",
)
# result["emotion"] 是七维归一化情绪向量

trajectory = memory.get_emotion_trajectory("patient-001", limit=100)

context = memory.get_context_for_llm("patient-001")
snapshot = memory.get_memory_for_user("patient-001")

memory.update_mmse_score(
    "patient-001",
    score=24,
    weak_dimensions=["延迟回忆", "计算力"],
)
memory.add_comfort_strategy(
    "patient-001",
    "聊孙子近况",
    effective=True,
)
```

`capture_turn()` 会保存会话 ID、时间戳、用户/助手消息和情绪历史；`get_context_for_llm()` 会按会话和时间标识近期对话，并限制上下文长度。

## HTTP API

记忆 API 使用现有登录认证：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/memory/{patient_id}` | 查看完整记忆 |
| GET | `/api/memory/{patient_id}/context` | 查看注入 LLM 的上下文 |
| PATCH / PUT | `/api/memory/{patient_id}` | 修改 `profile/facts/preferences/events/narrative` |
| POST | `/api/memory/{patient_id}/mmse` | 追加 MMSE 记录，分数范围 0-35 |
| POST | `/api/memory/{patient_id}/comfort-strategies` | 记录安抚策略及有效性 |
| GET | `/api/memory/{patient_id}/emotion-trajectory` | 查询七维情绪、效价和唤醒度轨迹 |

更新请求示例：

```json
{
  "updates": {
    "profile": {"age": 71},
    "preferences": ["听戏曲", "散步"],
    "narrative": "用户确认愿意聊家庭近况。"
  }
}
```

## 前端组件

语音系统的 `8502` 页面已经内嵌记忆管理。登录后从语音页面进入“记忆管理”，可查看长期记忆、本次会话和本轮进度，并通过 `GET/PATCH /api/memory/{patient_id}` 及逐条 item API 管理记忆。`frontend/src/components/MemoryCard.vue` 仅用于源码维护和构建验证，不是用户必须单独启动的入口。

仓库仍保留 Vue 3 + Vite 前端工程用于源码维护和构建验证，MMSE 趋势使用原生 SVG，不额外引入 ECharts 依赖。用户不需要单独启动这个工程；统一运行入口如下：

```powershell
cd frontend
npm install
npm run build
```

用户访问 `http://127.0.0.1:8502/`，登录后从语音页面的抽屉进入“记忆管理”。`frontend/` 的开发服务器仅用于调试源码；如果确需调试，才使用 `npm run dev`，它不是完整语音系统的入口。`8000` 仅在启用 SoulX 轮次服务时使用。

## 配置

```text
MEMOBASE_PROJECT_URL=http://127.0.0.1:8019
MEMOBASE_API_KEY=<与 ACCESS_TOKEN 相同的值>
EMOTION_USE_TRANSFORMERS=false
USE_MODELSCOPE=false
EMOTION2VEC_MODEL=iic/emotion2vec_plus_large
```

本地 Memobase、PostgreSQL 和 Redis 的启动、健康检查与数据目录见[本地 Memobase 部署](memobase-local.md)。未配置 Memobase 服务时，系统仍可使用本地 SQLite 和规则情绪识别。启用 Emotion2Vec+ 前，应安装 `requirements-emotion.txt`，并确认模型已下载到项目目录或允许的缓存目录。模型不可用时语音轮次自动回退到文本情绪。
